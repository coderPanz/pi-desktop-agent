# Seatbelt 沙箱的生效方式

**结论**：macOS 的沙箱是**内核挂在进程上的 MAC 标签**。`sandbox-exec -f profile <程序> <参数…>` 在同一进程里给
自己挂标签，然后 `execvp` 成目标程序——没有残留的包装进程；标签随 `fork`/`execve` 继承，子进程**只能更严，不能更宽**。

## 依据（macOS 26.2 实测）

**1. 它不是一个常驻的包装进程**

```bash
$ sandbox-exec -f e.sb sh -c 'sleep 3' &
$ ps -o pid=,ppid=,comm= -p <那个 pid>
8038     1 sleep          # 既没有 sandbox-exec，也没有多一层；它已经 execvp 成 sleep
```

**2. 换二进制也甩不掉标签**

```bash
$ sandbox-exec -f e.sb sh -c 'exec /bin/zsh -c "echo x > /private/tmp/outside/z.txt"'
zsh:1: operation not permitted: /private/tmp/outside/z.txt     # 换解释器照样被拦
```

**3. 沙箱内不能给自己放宽**

```bash
$ sandbox-exec -f e.sb sh -c 'sandbox-exec -p "(version 1)(allow default)" sh -c "…"'
sandbox-exec: sandbox_apply: Operation not permitted           # 退出码 71
```

嵌套只会取交集，所以「用内层 profile 放宽」这条路不存在。

**4. setuid 二进制在沙箱里不能执行**

```bash
/bin/ps  是 -rwsr-xr-x（setuid root）
$ sandbox-exec -f e.sb /bin/ps        → sandbox-exec: execvp() of '/bin/ps' failed: Operation not permitted
$ sandbox-exec -f e.sb /bin/ls        → 正常
$ sandbox-exec -f e.sb /usr/bin/sudo  → 退出码 71；/usr/bin/login 同
```

这是内核的保护：setuid 等于提权，等于绕过整份策略，所以直接禁止 exec。
副作用：**沙箱内的 `bash` 用不了 `ps` / `top` / `sudo` / `login`**，要排查进程得换不需要提权的命令。

## 推论（写 profile 时要注意）

- 安全性的全部重量在 **profile 正确性**上：`(allow file-write* (subpath "/"))` 这种写法等于没沙箱；
  标准写法是 `(deny file-write*)` 打底，再**窄**放开。
- 路径要传 **realpath**：标签匹配的是内核解析后的路径，`/var/…` 与 `/private/var/…` 是同一处。
- `sandbox-exec` 是 Apple 的 deprecated API（只是仍然可用）。用它的地方必须**探测 + 失败即拒**，
  不能静默降级成无沙箱——否则用户以为自己被保护了。
