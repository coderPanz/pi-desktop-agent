# Seatbelt 策略能拦什么、不能拦什么

**结论**：一份典型的最小权限 profile（`(deny file-write*)` + 只放开工作区与临时目录 + `(deny network*)`）能挡住
**写工作区外**和**联网**，连软链绕过和整棵子进程树都挡得住；但**读是全局的**、**工作区内的破坏不管**，
而且它只管得到子进程，管不到主进程自己的文件操作。

## 能拦（都在内核里判定，绕不过命令行）

| 操作 | 实测结果 | 说明 |
|---|---|---|
| 写工作区外 | `Operation not permitted`，退出码 1 | `(deny file-write*)` + 窄放行 |
| 通过工作区里的软链写到外面 | 拒绝 | 按内核解析后的真实路径匹配，`ln -s /` 这类把戏无效 |
| 多层子进程里的写 | 拒绝 | `sh -c 'sh -c "echo > /etc/x"'` 同样失败，标签随 fork 继承 |
| 改 `~/.zshrc` 之类持久化 | 拒绝 | 家目录不在允许列表里 |
| 联网 | 连接失败（`deny network*`） | 拦在 socket 层，`curl` 拿不到地址 |
| setuid 二进制 | `execvp … failed: Operation not permitted` | `ps` / `sudo` / `login` 属此类，见第 1 篇 |

## 不能拦（不要误以为安全）

| 场景 | 为什么 | 该由谁管 |
|---|---|---|
| **读密钥文件**（`cat ~/.ssh/id_rsa`） | profile 不动 `file-read*`（动了会误伤 git、缓存、`node_modules`） | 要堵得加第二档读规则；本项目用「`read` 工具只能读工作区」这条应用规则兜一半 |
| **工作区内被破坏**（`rm -rf .`） | 工作区是允许写的地方 | 审批策略 + git 快照 |
| **主进程自己的文件操作**（`write`/`edit` 工具、写 SQLite） | 它们不经过子进程，没有标签 | 应用层路径边界（`paths.ts` + `guard.ts`） |
| **模型 API 的出口流量** | 主进程必须联网调模型 | 无法沙箱化；只能靠"别把敏感内容读出来" |
| 临时目录里的写 | 故意放行（工具都要用 `$TMPDIR`） | 想更严可以改成只放开 workspace 下的子目录 |

## 两个容易踩的细节

1. **`$TMPDIR` 可写**：用 `/tmp` 验证"写工作区外会被拒"会得到成功，误判成沙箱没生效。
   验证要用家目录或 `/etc` 这类路径。
2. **profile 写宽 = 没有沙箱**：安全边界完全取决于那十几行策略，代码里那层装饰器只负责"把策略挂上去"。
