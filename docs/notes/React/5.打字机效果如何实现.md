# 打字机效果如何实现

**一句话**：文本一直在手里，只是**只显示前 n 个字**，定时把 n 加一。

```tsx
function Typewriter({ text }: { text: string }) {
  const [n, setN] = useState(0)

  useEffect(() => {
    setN(0)                                   // 换了新文本，从头打
    const timer = setInterval(() => {
      setN(v => (v >= text.length ? v : v + 1))
    }, 30)                                    // 30ms 一个字
    return () => clearInterval(timer)         // 卸载/换文本时清掉
  }, [text])

  return <p>{text.slice(0, n)}</p>
}
```

就这么点东西：

1. `text` 是完整文本，不用管它怎么来的（用户输入、接口返回、模型流式都行）。
2. 状态只有一个数字 `n`：已经打了几个字。
3. 每次 `n` 变化，`slice(0, n)` 就多露出一个字，看起来就是在「打字」。
4. 速度 = 定时器间隔；改 30ms 就慢一点，改 10ms 就快一点。

## 几个必要的细节

- **清定时器**：`return () => clearInterval(timer)`，否则组件卸载后还在跑。
- **结束就停**：`v >= text.length` 时不要再加，不然会一直空转。
- **重置**：`text` 变了要把 `n` 归零，否则新内容直接整段出现。
- **流式文本**：直接传当前已收到的文本；文本变长时打字机自己继续追。


## 想快一点/一次多打几个字

把「每次 +1」改成按时间算：

```tsx
useEffect(() => {
  const id = setInterval(() => {
    setN(v => Math.min(text.length, v + 2))  // 一 tick 打 2 个字
  }, 30)
  return () => clearInterval(id)
}, [text])
```

## 如果内容是 Markdown

别在字符串里插标记，直接用「切好的文本」重新渲染 Markdown：

```tsx
<Markdown>{text.slice(0, n)}</Markdown>
```

打字机只负责「显示多少个字」，渲染交给原来的 Markdown 组件。

## 疑问：每次都重新渲染，为什么原来的字不会闪

因为 **重渲染 ≠ 重建 DOM**。React 一次更新分三步：

1. **render**：再跑一遍组件函数，得到新的元素树（纯 JS 对象，跟 DOM 无关）；
2. **diff**：新树和上一次的树比较；
3. **commit**：**只把差异写到真实 DOM**。

打字机每 tick 的差异长这样：

```
<p>abc</p>   →   <p>abcd</p>
```

- `<p>` 类型、位置、props 都没有变 → React **复用同一个 DOM 节点**，不卸载、不重建；
- 子节点都是一个文本节点，内容从 `"abc"` 变成 `"abcd"` → React 做的就一句：

```js
textNode.nodeValue = "abcd"   // 就地改，没有 remove / create
```

没有节点被删除或新建，没有 `opacity`/`display` 变化，所以浏览器只是重排重绘一次：**已有的字一个像素都不动，右边多画一个字**。看起来就是"多打了一个字"。

另外，一次 `setState` → 一次同步 commit → 浏览器要等控制权交回才绘制一帧。中间"已改 state 还没改 DOM"的状态永远不会被画出来，所以也不会出现「先空白再出现」。

### 什么时候才会真的闪

只有 DOM 节点被销毁重建时才会闪：

- 元素**类型换了**：`{loading ? <Spinner/> : <p>…</p>}`；或把组件内联成每次新建的箭头函数（类型身份变了 → 卸载 + 重挂）；
- **`key` 变了**：`key={Math.random()}`、列表顺序变化；
- 元素**结构/位置变了**：外面多包一层 `div`、兄弟节点增删；
- 绕过 React 直接 `el.innerHTML = …`：整段重新解析重建；
- 节点重挂时 CSS 动画从头播一遍（看着像闪一下）。

**一句话**：React 重渲染是重新计算，DOM 只打补丁；打字机每次的补丁就是"那个文本节点多了一个字符"。
