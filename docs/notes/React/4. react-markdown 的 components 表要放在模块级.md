# react-markdown 的 `components` 表不能写在组件内部

**结论**：`<Markdown components={{ p: ({children}) => <p>{children}</p> }}>` 这种写法，每次渲染都会传进一个**新的函数引用**，React 把它当成换了元素类型，于是整棵 Markdown 子树卸载重建。

## 依据

`react-markdown` 把 `components` 里的每个函数原样当成 React 元素类型交给 `hast-util-to-jsx-runtime` 的 `create(node, type, props, key)`（`node_modules/.pnpm/react-markdown@10.1.0*/node_modules/react-markdown/lib/index.js`，`state.create` 直接 `createElement(type, ...)`）。类型引用变了 → 同一位置上的旧元素与新元素类型不相等 → 卸载 + 挂载，不是更新。

## 什么时候会咬人

- 流式输出：每次收到新 token 都重新解析一遍 Markdown，子树整棵重建，任何 CSS 动画都会从头重播（打字机/进场动画会一直闪）。
- 交互状态：子树里如果有 `<details>` 展开、`<details open>`、文本选区、`<pre>` 横向滚动位置，全部被重置。
- 性能：每次更新都是全量 DOM 重建，而不是 diff。

## 做法

- `components` 表放模块级常量（`apps/desktop/src/renderer/src/components/Markdown.tsx` 的 `COMPONENTS`），组件需要的外界信息通过 props/context 传进去。
- 插件要按渲染传参时用 `rehypePlugins={[[plugin, options]]}`，插件只改 hast，不新增元素类型。
- 想在 hast 层包出稳定结构（如逐词 span），也放在 rehype 插件里做：位置稳定，React 才会按位置复用节点。
