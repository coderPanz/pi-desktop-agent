# main、preload、renderer 三层的作用和设计目的

## 三层各做什么

| 层 | 作用 |
|---|---|
| `src/main` | 主进程，跑在 Node 里，拥有完整系统权限。负责窗口创建、应用生命周期、读写文件 / 数据库、跑 agent 运行时。 |
| `src/preload` | 预加载脚本，在页面脚本执行前跑。用 `contextBridge` 把主进程的能力挂成 `window.pi`，是页面和主进程之间唯一的通道。 |
| `src/renderer` | 渲染进程，跑在 Chromium 里。就是 React 写的界面，只能调 `window.pi`，没有任何 Node 能力。 |

## 为什么这样设计

1. **安全边界**。渲染进程要加载的可能是不受信的页面内容，所以给它开 `sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`——页面里没有 `require`、没有 `fs`。想碰系统能力只能经过 preload 显式暴露的少数方法。

2. **权限最小化**。preload 只暴露具体方法，不暴露 `ipcRenderer` 本体，这样页面就无法往任意通道发消息，IPC 契约才守得住。

3. **运行环境本来就不同**。main 是 Node，renderer 是浏览器，两边的模块系统和可用 API 完全不同。preload 是夹在中间的那层，天然要被单独对待。

4. **构建方式因此也不同**。main 打成 ESM，preload 必须是 CJS（沙箱下没有 ESM），renderer 交给 Vite（JSX / CSS / npm 包）。所以源码也必须分目录，否则产物没法对齐。

一句话：三层不是代码风格分层，而是 **Electron 的进程隔离模型**决定的——主进程持权、preload 当桥、renderer 只画界面。
