# file 协议

`file:` 是**本机绝对路径的 URL 写法**。它不是网络协议，只是把磁盘路径换成 URL 语法，好让 `import()`、`fetch()`、`location` 这类只认 URL 的接口能接受它。

```
file:///Users/tal/Desktop/a.md
└┬─┘ └┬┘ └───── pathname ─────┘
 │    └ host 为空 → 所以是三个斜杠
 └ scheme
```

`file://localhost/路径` 与 `file:///路径` 等价；Windows 是 `file:///C:/Users/x`。

## 路径与 URL 不能手工拼接

URL 里空格、中文、`#`、`?`、`%` 都有语法含义（`#` 之后是 fragment、`?` 之后是 query、`%` 是转义开头），所以路径段必须百分号编码：

```
/Users/tal/pi agent/笔记.md
→ file:///Users/tal/pi%20agent/%E7%AC%94%E8%AE%B0.md
```

转换只用两个函数：`pathToFileURL(path)` 转过去，`fileURLToPath(url)` 转回来。`pathname` 里是未解码的形式，直接当文件路径用会失败。

## query 和 hash 不属于路径

`fileURLToPath()` 忽略 `?` 与 `#` 部分，所以 `file:///a.mjs?v=2` 读的仍是 `a.mjs`。

但 query 会参与 ESM 的模块缓存键：同一文件 `?v=1` 与 `?v=2` 是两个独立实例。这就是「热替换工具」时给 import URL 加版本号的原因——URL 不变，拿到的永远是旧代码。

## 在 Electron 里它不是「不透明源」

浏览器里 `file://` 页面的 origin 是 `null`，所以读别的本地文件会被拦。Electron（开启 `webSecurity`、`sandbox`）里 `location.origin` 就是 `file://`，页面能直接读到本机其它文件。

因此本地文件的安全性不能依赖同源限制，只能依赖：只加载本地文件、不把不可信内容当 HTML 渲染、要读文件就走 IPC。
