# file 协议

`file:` 是**本机路径的 URL 表示**。它在本项目里出现在四个地方：Electron 加载渲染进程、preload 的挂载、Node 动态 `import()` 用户工具、以及由 `import.meta.url` 反推目录。

铁律：**路径不是 URL。** 中文、空格、`#`、`?`、`%` 都会被 URL 语法吃掉或改写，所以拼接 `"file://" + p` 一定会错；一律用 `pathToFileURL(path)` 转过去、`fileURLToPath(url)` 转回来。

---

## 1. URL 的形状

```
file:///Users/tal/Desktop/pi%20agent/%E7%AC%94%E8%AE%B0.md
└┬─┘└┬┘└────────────── pathname（百分号编码）────────────────┘
 │   └ host 为空（所以是三个斜杠）
 └ scheme
```

| 形态 | 说明 |
|---|---|
| `file:///abs/path` | macOS / Linux 的常规形态 |
| `file://localhost/abs/path` | 等价可用（Chromium 实测同源，见 §5） |
| `file:///C:/Users/x` | Windows；`fileURLToPath` 会还原成 `C:\Users\x`（未在本机验证） |
| `file:relative/path` | 合法但极少用；`pathname` 为相对路径，行为取决于消费方，不要用 |

---

## 2. 项目里出现 file 协议的四个位置

| 位置 | 代码 | 注意 |
|---|---|---|
| Electron 加载页面 | `win.loadFile(p)` / `win.loadURL(...)` | `loadFile` 接收**文件系统路径**，Electron 内部转成 file URL；加载后 `location.href` 与 `document.baseURI` 都是 `file:///…` |
| preload | `webPreferences.preload` | 收的是**绕对文件路径**，不是 URL；传相对路径或 `file://` 会被拒绕（Electron 报 `preload script must have absolute path.`） |
| Node 动态 import 工具 | `import(pathToFileURL(file).href + "?v=" + version)` | `?v=` 不影响读到哪个文件，但能骗过 ESM 缓存（见 §4） |
| 主进程反推目录 | `fileURLToPath(new URL("..", import.meta.url))` | `import.meta.url` 本身就是 `file:///…` 字符串 |

反例（都会坏）：

```ts
// ✗ 中文路径里出现 # 或 ? 时被当成 fragment / query
const mod = await import("file://" + toolPath)
// ✗ 相对路径 + 手工拼协议
const url = `file://${path.resolve(root, rel)}`
```

## 3. 编码：为什么必须用 `pathToFileURL`

实测（Node 22.22，`node:url`）：

| 原始路径 | `pathToFileURL(p).href` |
|---|---|
| `/Users/tal/Desktop/pi agent/笔记.md` | `file:///Users/tal/Desktop/pi%20agent/%E7%AC%94%E8%AE%B0.md` |
| `/tmp/中文 空格 #号 ?问号.md` | `file:///tmp/%E4%B8%AD%E6%96%87%20%E7%A9%BA%E6%A0%BC%20%23%E5%8F%B7%20%3F%E9%97%AE%E5%8F%B7.md` |

`pathname` 里是**未解码**的百分号形式；要拿可读路径用 `decodeURIComponent(pathname)`，要拿可用的文件系统路径用 `fileURLToPath()`。

手工拼接的三种坏法：

- `#` → 被当成 fragment，路径在这里被截断；
- `?` → 被当成 query，同上；
- `%` → 被当成转义序列开头（原生文件名里带 `%` 时尤其危险）。

空格与中文属于「多数实现碰巧容忍」，**不能依赖**。

## 4. query / hash 与路径的关系

| 事实 | 实测 |
|---|---|
| `pathname` 不含 search / hash | `file:///a/mod.mjs?v=2` → `pathname = /a/mod.mjs` |
| `fileURLToPath` 忽略 search / hash，不抛错 | 返回 `/a/mod.mjs` |
| `fs.readFileSync(URL)` 接受 file URL，带 query 也能读 | 读到同一份内容 |
| query 参与 ESM 模块缓存键 | 同一文件 `?v=1`、`?v=2`、无 query = **三个独立实例**；相同 URL 复用同一实例 |

最后一条是阶段 8「工具热替换」的基础：

```ts
// 只要 query 变了，ESM 就当它是另一个模块，重新求值
const mod = await import(pathToFileURL(toolFile).href + `?v=${version}`)
```

推论：**不要靠删文件/清缓存来换实现**，也不要给同一个 URL 期望拿到新代码。

## 5. Electron 里 `file://` 不是「不透明源」（与浏览器相反）

实测条件：Electron 45.0.0，`loadFile` 加载本地 `dist/renderer/index.html`，`webSecurity: true`、`sandbox: true`、`contextIsolation: true`，隐藏窗口 + `executeJavaScript` 取值。

| 观测 | 结果 |
|---|---|
| `location.origin` | `file://`（**不是** `"null"`） |
| `window.isSecureContext` | `true` |
| `crypto.randomUUID()` | 可用（依赖 secure context） |
| `localStorage` | 可用 |
| `fetch(location.href)` | 200 |
| `fetch("file:///etc/hosts")` | 200，**能读内容** |
| `fetch("file://localhost/etc/hosts")` | 200 |
| `XMLHttpRequest` 读 `file://` | 200 |
| CSP `default-src 'self'` 下加载自身 css/js | 正常（样式表 1 个、脚本执行） |

含义：**渲染进程对本机所有文件是「同源可读」的**，CORS 在 file:// 里不构成边界。

于是三条项目规则不能省：

1. **只加载本地文件**，`loadURL` 远程地址 = 一旦被 XSS 就能读全盘；
2. **不把不可信内容当 HTML 渲染**（不用 `dangerouslySetInnerHTML`、不 `eval`）；模型输出的 `details`、TokUI DSL 都是不可信输入；
3. **渲染进程要文件就走 IPC**（主进程读、主进程写），保持「主进程是唯一写者」。

CSP 仍然要配（挡外部资源），但要清楚它**挡不住 file:// 之间的互相访问**。

## 6. 什么时候不该用 file://

| 需求 | 为什么 file:// 不行 | 替代 |
|---|---|---|
| 正常的 CORS / 同源隔离 | 本地一切同源（§5） | 自定义协议（`app://`）或 `http://localhost` |
| Service Worker / 完整 storage 隔离 | file:// 不支持或行为受限 | `app://` + `protocol.handle` |
| 渲染进程读工作区文件 | 绕过主进程 = 破坏单写者 | IPC → `NodeExecutionEnv` |
| 从用户目录加载工具代码 | 渲染进程不该执行特权代码 | 主进程 `import(pathToFileURL(...))` |

## 7. 排查对照

| 现象 | 根因 | 修法 |
|---|---|---|
| 窗口白屏，`did-fail-load` 里路径像 `file:///…/%E4%B8%AD…/index.html` 但文件其实存在 | 路径拼错 / 产物目录结构变了 | 用 `loadFile(绝对路径)`；产物保持 `dist/{main,preload,renderer}` 同级 |
| `ERR_UNSUPPORTED_ESM_URL_SCHEME` | 给 `import()` 传了裸路径（`/Users/...`） | `pathToFileURL(p).href` |
| `ERR_MODULE_NOT_FOUND` 但文件在 | 手工拼 URL 时 `#`/`?` 截断了路径 | 同上，不拼字符串 |
| 工具热替换后仍跑旧代码 | URL 没变，命中 ESM 缓存 | query 里带版本号（§4） |
| preload 没生效、`window.pi` 是 undefined | `preload` 传了 `file://` 而非路径；或产物是 ESM | 传路径；preload 产物必须是 CJS |
| 打包后动态 import 失败 | asar 内路径仍是 `file:`，但需正确构造 | 继续用 `pathToFileURL`；必要时 `asarUnpack` |

## 8. 一行验证

```bash
# 编码与还原
node -e "const{pathToFileURL,fileURLToPath}=require('node:url');const u=pathToFileURL('/tmp/中文 空格 #号.md');console.log(u.href);console.log(fileURLToPath(new URL(u.href+'?v=1')))"

# ESM 缓存键：?v= 会造出独立实例
node -e "const{pathToFileURL}=require('node:url');const{writeFileSync}=require('node:fs');writeFileSync('/tmp/m.mjs','globalThis.n=(globalThis.n??0)+1;export const n=globalThis.n');const b=pathToFileURL('/tmp/m.mjs').href;import(b+'?v=1').then(a=>import(b+'?v=2').then(c=>console.log(a.n,c.n)))"
```

Electron 侧（origin / fetch 能力）需要真跑一次窗口：建隐藏 `BrowserWindow` → `loadFile` → `webContents.executeJavaScript` 读 `location.origin` 并 `fetch("file:///etc/hosts")`。§5 的表就是这么来的。
