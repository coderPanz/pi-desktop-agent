# process 是什么

`process` 是 Node.js 提供的**全局对象，不需要 import**，代表「当前正在运行的这个进程」：它是谁、用什么版本跑、启动参数是什么、环境变量有什么、怎么退出。类比浏览器里的 `window` / `document`，只不过它描述的是进程层而不是页面。

Electron 里它同时是 Node 的 `Process` 和 Electron 扩展过的 `Process`（多出 `type`、`sandboxed`、`defaultApp`、`resourcesPath`、`versions.electron/chrome`），见 `apps/desktop/node_modules/electron/electron.d.ts` 的 `interface Process extends NodeJS.EventEmitter`（约 28234 行起）。

## 常用成员

| 成员 | 含义 | 本项目用例 |
|---|---|---|
| `process.env` | 环境变量表，类型是 `Record<string, string \| undefined>` | `process.env.PI_DEV_SERVER_URL` 决定渲染层走 dev server 还是本地文件 |
| `process.argv` | 启动参数 `[可执行文件, 脚本路径, ...真实参数]` | `process.argv.includes("--dev")` |
| `process.versions` | `{ node, electron, chrome, ... }` | 启动日志、`DesktopRuntime` 的 `versions` 字段 |
| `process.platform` | `"darwin" \| "win32" \| "linux"` | 判断是否 macOS，决定 `titleBarStyle` / 背景色 |
| `process.exit(code)` | 立即结束进程 | 构建脚本兜底 / 跟随 Electron 退出码 |
| `process.on("SIGINT" \| "SIGTERM")` | 监听进程信号 | dev 脚本 Ctrl+C 时优雅关 server |
| `process.execPath` | 当前可执行文件绝对路径 | 测试里用它再 spawn 一个 Node |
| `process.cwd()` / `chdir()` | 当前工作目录 | 测试里切目录验证 `.env` 查找 |
| `process.type` | `browser` / `renderer` / `worker` / `utility`（Electron 扩展） | 只借类型判断当前在哪种进程 |

## 不同进程里 `process` 的能力不一样

这是 Electron 项目最容易搞混的部分，同一份代码在三个地方权限完全不同：

```
主进程（electronExe 直接跑的主入口）
  → 完整 Node 的 process：env、argv、fs、child_process 全可用

沙箱 preload（sandbox: true）
  → 精简 process：主要是只读信息（platform / versions / sandboxed / type），
    没有完整的 Node API

渲染进程（nodeIntegration: false + sandbox: true）
  → 完全没有 process（也拿不到 require / fs）
```

本项目的 `webPreferences` 就是 `contextIsolation: true` + `nodeIntegration: false` + `sandbox: true`（`apps/desktop/src/main/index.ts:110-114`），所以渲染进程要拿版本、平台这类信息只能走 IPC，不能自己读 `process`。preload 目前也完全没碰 `process`（`apps/desktop/src/preload/index.ts`）。

## 环境变量是怎么传进主进程的

`spawn` 的 `env` 选项**整体替换**子进程环境，所以必须展开父进程环境再叠加，否则 `PATH`、`HOME`、`TMPDIR` 会丢：

```ts
// apps/desktop/build/build.ts:111-119
spawn(electronExe, [appRoot], {
  stdio: "inherit",
  env: {
    ...process.env,                       // 不展开会丢掉 PATH 等
    ...(devServerUrl === undefined ? {} : { PI_DEV_SERVER_URL: devServerUrl }),
  },
})
```

主进程侧只有一条读取路径（`apps/desktop/src/main/index.ts:31`）：

```ts
const devServerUrl = process.env.PI_DEV_SERVER_URL   // 模块顶层读一次
// ...
if (devServerUrl !== undefined) await created.loadURL(devServerUrl)
else await created.loadFile(path.join(mainDir, "../renderer/index.html"))
```

即「父进程 spawn 时塞进 env → 子进程继承 → 主进程用 `process.env` 读」，没有 argv、配置文件或 IPC 参与。

## 两个易错点

1. **`process.env` 的值永远是字符串**。`PI_LOG_LEVEL=0`、`X=false` 都是真值字符串，判断必须写 `=== "debug"` 或 `!== undefined`，不能直接 `if (process.env.X)` 当布尔。
2. **`process.env` 是启动时的快照**（本进程可写，但只影响之后 spawn 的子进程）。所以 dev 模式下改主进程代码只能 kill + respawn，改环境变量对已运行的进程无效——这也正是 `runDev()` 里 `restart()` 存在的理由。
