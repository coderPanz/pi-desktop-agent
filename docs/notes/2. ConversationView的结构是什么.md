# ConversationView 的结构是什么

`ConversationView` 是 PI-Durable 为**一个会话**构造的只读结构视图。实际类型定义位于 `@earendil-works/pi-durable/dist/harness/view.d.ts`：

```ts
type ConversationView = {
  readonly conversation: ConversationRecord;
  readonly entries: readonly EntryRecord[];
  readonly docs: Readonly<Record<string, JsonObject>>;
};
```

## 字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `conversation` | `ConversationRecord` | 当前会话的记录。 |
| `entries` | `readonly EntryRecord[]` | 当前活跃转录。数组包含 head 标记，以及从该 head 开始的非 head 条目。 |
| `docs` | `Readonly<Record<string, JsonObject>>` | 内置会话文档，以文档 `kind` 为键保存。文档不存在时不会出现在该对象中。 |

三个字段及其容器都声明为只读；它是用于观察和展示的视图，不应在调用方修改。

## `docs` 的已挂载文档

实现文件 `dist/harness/view.js` 的 `MOUNTED` 常量只挂载以下五个内置文档：

```text
pi.agent
pi.live
pi.inbox
pi.provider
pi.usage
```

`docs` 的值在类型层面统一是 `JsonObject`，不会按 `kind` 自动收窄为具体文档类型。因此读取 `pi.live` 等字段前，需要由调用方只访问已确认的字段或自行做运行时校验。

## 视图如何构成

创建会话视图时，实现会：

1. 读取指定会话的 `ConversationRecord`；
2. 读取该会话当前上下文边界内的活跃 `entries`；
3. 依次加载上述五种内置文档中实际存在的文档；
4. 组合为 `{ conversation, entries, docs }`。

后续提交发布时，视图会把文档变更转换到 `docs.<kind>` 路径，并把会话 entry 变更转换到 `entries` 路径；订阅者因此能收到该视图的增量操作。

## 获取方式

`Conversation` 提供两种同一结构的观察入口：

```ts
const state = await conversation.viewState(ctx); // 本进程的 AttachedReplicatedState<ConversationView>
const watch = await conversation.watch(ctx); // 带 value 和 ops 的 WatchHandle<ConversationView>
```

`viewState()` 与 `watch()` 都观察 `ConversationView`；后者额外提供每次更新对应的 `ops`，适合把变化同步到进程外的副本。
