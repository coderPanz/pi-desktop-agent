# 什么是 replica
`replica` 是“副本”。 它是观察者根据会话更新维护的一份本地 `ConversationView` 副本。

```ts
export type Replica = ConversationView;
```

## 建立副本
订阅建立时，`watch.value` 是当前完整视图，可作为副本初值：

```ts
const watch = await root.watch(ctx);
let replica: Replica = watch.value;
```

之后，观察者将每一帧的 `ops` 应用到上一版副本，产生下一版副本：

```text
上一版 replica + ops = 下一版 replica
```

应用必须是不可变的：旧副本保持不变，新副本替换旧副本引用。

## 结构组成
副本的形状就是 `ConversationView`，由三块组成：

```text
replica
├─ conversation  会话记录（id、parent、owner）
├─ entries       当前活跃转录（只读数组）
└─ docs          内置文档（按 kind 索引）
```

```ts
type Replica = {
  conversation: ConversationRecord; // 会话自身记录。
  entries: readonly EntryRecord[]; // 当前活跃转录，已提交的部分。
  docs: Readonly<Record<string, JsonObject>>; // 内置文档，按 kind 索引。
};
```

### 完整结构示意
下面是实测输出的形状（值取自一次真实运行，已缩短；字段名与层次与 SDK 一致）：

```ts

  conversation: {

  // ── 2. 活跃转录（已落盘） ───────────────────────────
  entries: [
    {
      model: [{ role: "user", content: "用一句话说明什么是副本。", timestamp: 1792848019453 }], // 交给模型的消息。

      id: 7, // 条目 id，单调递增。
      conversationId: 1, // 所属会话。
    },
    {
      model: [
        {
          role: "assistant",
          content: [{ type: "text", text: "副本是独立于主世界的私有实例空间。" }], // 内容块数组。
          api: "anthropic-messages",
          provider: "gateway",
          model: "deepseek-v4.1-flash",
          usage: {
            input: 10,
            output: 30
          },
          stopReason: "stop", // 工具轮时是 "toolUse"。
          timestamp: 1792848019516,

  docs: {

        inputs: [8], // 属于本轮运行的提交 id。

        attempt: 1, // 第几次尝试，重试会自增。

          role: "assistant",

          api: "anthropic-messages",

    // 排队输入；空闲时是 { items: [] }。
    "pi.inbox": {
      items: [],

      sessionId: "01a16e11-bffa-71a1-9a2d-f8ec79928a3c",
    },

    // 用量账本：按 "provider/modelId" 与工具名分组。
    "pi.usage": {
      models: {
        "gateway/deepseek-v4.1-flash": {
          input: 10,
          output: 30,

      tools: {},

```

读这份结构时有三条约定：

- **缺席，不是 `undefined`。** 经过 JSON 后，值为 `undefined` 的字段直接消失。所以判断「有没有」要用 `in` 或真值判断，不要假设键存在。
- **`pi.live` 空闲时是 `{}`。** 不是被删掉，而是内容清空；判断是否在跑要看 `live.run`。
- **`docs` 的值类型统一是 `JsonObject`。** 上面的内部字段来自库的类型定义，读取前要自己确认存在性。

### `entries`：已落盘的转录

按时间顺序保存的 `EntryRecord`。`kind` 由系统或应用定义，内置的有：

| kind | 含义 |
|---|---|
| `pi.user` | 用户输入 |
| `pi.assistant` | 模型回答（`model` 是消息数组） |
| `pi.tool-result` | 工具执行结果 |
| `pi.system` | 系统提示 |
| `pi.reset` | 重置标记 |
| `pi.compaction` | 压缩摘要 |

`pi.assistant` 的文本在 `model[0].content` 里，`content` 是内容块数组，不是字符串。

### `docs`：随帧一起到的内置文档

实际运行时观察到的键（阶段 1 启动日志）：

```text
pi.agent     当前 agent 配置
pi.live      运行中的回答、工具槽位、排队状态
pi.inbox     待处理输入
pi.provider  模型来源状态
pi.usage     token 用量
```

`docs` 的值类型统一是 `JsonObject`，不会按 `kind` 自动收窄，读取前需自行确认字段。文档不存在时该键直接缺席，不是 `undefined`。

### 三块的分工

| 区域 | 什么时候变 | 显示什么 |
|---|---|---|
| `entries` | 一次提交完成、正式落盘时 | 稳定的历史消息与工具结果 |
| `docs["pi.live"]` | 生成过程中持续变（约 100ms 一批） | 流式回答、运行中工具状态 |
| `docs` 其余键 | 配置、排队、用量变化时 | 状态栏、排队提示、用量 |

所以渲染时要把「实时」和「正式」分开：生成中读 `pi.live`，落盘后读 `entries`，二者不能同时显示。
