# NodeExecutionEnv 是什么

```ts
new NodeExecutionEnv({ cwd: workspace });
```

它是一个**本地执行环境实例**，同时提供文件系统与 shell 两套能力。

| 能力 | 方法 |
|---|---|
| 文件系统 | `readTextFile` / `writeFile` / `listDir` / `exists` / `createDir` / `renameFile` / `canonicalPath` … |
| 执行命令 | `exec`（字符串走 shell，数组直接执行）、`cleanup` |

## 三个关键事实

1. **所有操作返回 `Result`，不抛异常**：`{ ok: true, value }` 或 `{ ok: false, error }`，因此调用处总是 `if (!read.ok)`。
2. **`cwd` 是实例字段，只决定相对路径的解析基准**：内部一律 `resolvePath(this.cwd, path)`，传绝对路径则原样使用；`exec` 的 `options.cwd` 同样相对 `this.cwd` 解析。
3. **所有本地环境共享 `id = "node:local"`**：看到的是同一批文件，新建实例不会读到旧快照。

## 构造参数

```ts
type NodeSqliteDatabaseOptions = { cwd: string; shellPath?: string; shellEnv?: NodeJS.ProcessEnv; watch?: NodeWatchOptions };
```

通常只需要 `cwd`。

## 在阶段 2 脚本里的四个用途

### 1. Harness 的 `env` 选项是工厂，不是实例

```ts
env: (target) => new NodeExecutionEnv({ cwd: target.cwd ?? workspace })
```

- 每次工具调用 / 请求准备时被调用一次，产出的对象就是工具里的 `api.env`。
- 构造很轻（只存字段、没有连接），所以每次新建是正常用法。
- `target.cwd` 是会话 agent 配置的 `cwd`；未配置时退回工作区，保证相对路径总有基准。

### 2. 脚本自建实例准备素材

```ts
const setupEnv = new NodeExecutionEnv({ cwd: workspace });
await setupEnv.createDir(..., { recursive: true }, ctx);
await setupEnv.writeFile(..., ctx);
```

此时还没进入工具调用流程，脚本直接写示例文件与工作区外的诱饵文件。

### 3. 另一个实例核对磁盘结果

```ts
const verifyEnv = new NodeExecutionEnv({ cwd: workspace });
const read = await verifyEnv.readTextFile(path.join(workspace, "hello.txt"), ctx);
```

用独立实例从磁盘读取，而不是相信工具返回的「已创建」，避免自证。

### 4. 伪造最小 `ToolExecutionApi`

```ts
const guardApi = { env: new NodeExecutionEnv({ cwd: workspace }) } as unknown as ToolExecutionApi;
await readTool.execute({ path: "../outside.txt" }, guardApi, ctx);
```

直接调用 `execute()` 时没有 Harness 提供的 api，只塞入 `env` 即可；工具里 `api.env.readTextFile(...)` 是真实执行的，因此越界拦截的验证不是假数据。

## `cwd` 不是沙箱

`NodeExecutionEnv` 允许访问工作区外的路径。边界必须由业务层守：

- 工具层：`resolveInside(workspace, path)` 拒绝越界与绝对路径；
- Hook 层：`classify(...)` 拒绝敏感目录与危险命令。

验收中 `../outside.txt` 被拒，靠的是 `resolveInside`，不是环境本身。

## 清理

`exec` 启动的子进程记录在实例的 `activeChildPids` 里，用完调用 `cleanup(ctx)` 杀掉残留进程。脚本准备阶段与单测中显式调用了它。

## 为什么每次调用都新建

构造只是赋值、状态只有 `cwd` 与 pid 记录，协调靠 `id` 而非对象身份，所以按 `HarnessOptions.env` 的契约每次新建：
见 [17. 为什么每次调用都新建 NodeExecutionEnv.md](./17.%20为什么每次调用都新建%20NodeExecutionEnv.md)。
