# pi-durable 调用流程

一次提问到拿到回答，按脚本里的真实调用顺序是 7 个必用 + 2 个可选。

## 准备阶段（一次）

### 1. `Harness.open(storage, { models, registry, settings }, ctx)`

把「存储 + 模型 + 工具 + 配置」组装成一个可运行的会话系统。

- `storage`：数据放哪里（内存或 SQLite）。
- `models`：能用的模型清单。
- `registry`：能用的工具清单。

此时还没有任何对话。

### 2. `harness.resume()`

打开调度，让排队的工作开始推进。不调用则任务只停在队列里。

### 3. `harness.root(ctx)`

拿到根会话。会话是「转录 + Agent 配置 + 文档」的组合，`root` 是默认那一个，持久化后重启不变。

需要新会话用 `harness.createConversation(...)`。

### 4. `conversation.configure({ model: { provider, modelId } }, ctx)`

指定这个会话用哪个模型。同一次调用还可以设置工具集、思考等级、指令、工作目录。

Harness 不会自动选模型，这一步必须显式做。

## 发问与回答

### 5. `conversation.watch(ctx)`（可选）

订阅会话，使回答能边生成边看到。不订阅也能拿到最终答案，只是最后一次性出现。

`watch.value` 是当前快照，`watch.start(回调)` 之后才开始收更新。细节见 [7. watch订阅.md](./7.%20watch%E8%AE%A2%E9%98%85.md)。

### 6. `conversation.submit({ type: "input", content, requestId }, ctx)`

把问题交进去，并建立一条可追踪的记录。它做三件事：

1. 往转录写一条用户消息（`pi.user`）。
2. 创建一条提交记录，返回 `submission`。
3. 会话空闲则立刻开始这一轮；正忙则按 `whenBusy` 排队（`followUp` 等本轮结束、`steer` 插队、`reject` 直接报错）。

`submit` 不调用模型，它只是收件。真正干活的是被唤醒的那一轮运行。

### 7. `submission.wait(ctx)`

等这一轮结束。返回值状态是 `done`（正常答完）或 `unanswered`（被撤回或没答）。此时答案已写入转录。

### 8. `conversation.entries(...)` 或 `conversation.context(ctx)`

从转录读已写入库的内容。

- `entries`：读消息历史，`pi.assistant` 是模型的回答。
- `context`：读模型本次真正看到的消息，用于排查上下文。

## 收尾

### 9. `harness.close(ctx)`

停止调度并释放存储。不关会留下定时器，进程退不掉。

## 顺序图

```text
Harness.open          装好：存储 + 模型 + 工具
     ↓
harness.resume()      开调度
     ↓
harness.root()        拿会话
     ↓
conversation.configure()   指定模型
     ↓
conversation.watch()  ─── 可选：订阅流式更新
     ↓
conversation.submit()     提问（写记录 + 建这一轮）
     ↓
submission.wait()         等这一轮跑完
     ↓
conversation.entries()    读答案
     ↓
harness.close()           关掉
```

## `submit` 之后内部发生了什么

1. 记下问题，并开启「这一轮」的工作。
2. 准备上下文：历史消息、系统提示、可用工具整理成一次请求。
3. 请求模型：回答边生成边分批写入「正在生成」的状态，订阅者因此能看到字幕式输出。
4. 收尾：回答完成后转为一条正式历史消息；若模型要求用工具，先执行工具再把结果带回模型，直到本轮结束。

## 三个随时可用的操作

| API | 作用 |
|---|---|
| `conversation.abort(ctx)` | 让正在跑的这一轮停止，已生成的部分保留 |
| `conversation.fork(at, ...)` | 从某条历史消息分叉出新对话 |
| `conversation.reset(handoff, ctx)` | 开新上下文，不携带旧历史 |

## 一句话总结

`submit` 只是把问题放进去；真正回答的是它背后自动开启的那一轮工作；`wait` 等它跑完；`entries` 把答案读出来。`watch` 非必需，但它是唯一能看到中间过程的入口。
