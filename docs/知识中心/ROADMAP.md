## 2. 待办（按依赖顺序）

### 2.1 运行时恢复与配置余项

默认启动、新建会话、终态错误三个阻塞项已修复。`pnpm test` 的 149 项检查已包含桌面纯 Node 装配、本地模型与 UI 静态渲染回归：新建后实际得到回答、无模型与最终失败状态、重试耗尽、排队不遮住当前失败、文件库重开、旧 root 补配置与保存的模型不被覆盖。

- 接入存储失败状态：观察 `HarnessHost.closed`，将 `SessionFailed` 变为不可继续使用的状态并提供重建/重启路径，不能只弹普通错误后继续发送
- 增加模型设置入口，并处理旧版留下的非 root 空模型会话；不能通过覆盖已保存模型来修复缺配置
- 安装包配置入口与分发验收仍未完成，开发仓库 `.env` 的加载不等于安装包配置支持

### 2.2 界面余项

主体已能用（消息、工具卡、审批、排队、流式、Markdown、调试条）。阻塞项之外还有体验细节：

- 会话列表只有 `#id` 与分叉来源：要显示首条用户消息摘要、最后活动时间；忙碌/排队标记需随任务结束刷新，当前会残留
- 自动重试与终态失败已有错误横幅，但没有「重试」按钮或倒计时
- 工具结果只能回看文本，没有「打开文件 / 复制路径」这类动作
- 没有键盘导航（切会话、聚焦输入框）与消息级操作（复制、引用、从某条分叉）
- 滚动是「有新内容就到底」，用户上翻查看历史时会被打断

### 2.3 崩溃恢复实测与打包

先把 `crashPoint(...)` 接入真实运行阶段，再为 `PI_CRASH_POINT` 五类场景各留重启恢复证据；随后 `pnpm package` 做打包冒烟，
确认 `node:sqlite` 在 asar 与打包后的路径/ABI 正常。

## 3. V1 不做

- 多窗口同时写同一会话（单写者下要额外做租约）。
- 云端同步、多设备。
- 多进程 / 多实例打开同一 SQLite 文件。
- 插件市场、远程安装工具包。
- 自定义模型协议（除 OpenAI 兼容的 provider 外）。
- 移动端。

这些是边界而不是承诺：先保证前四项不被架构分叉拖住。
