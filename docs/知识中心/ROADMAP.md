## 2. 待办（按依赖顺序）

### 2.1 运行时恢复与配置余项

默认启动、新建会话、终态错误与宿主失效处理已实现。失效时停止操作、结算待审批、清理订阅；
不访问失效存储即可返回失败快照，迟到健康响应不能覆盖失效状态。恢复只通过应用重启，不做进程内热重建。
项目不维护测试文件，默认验收为静态检查、CLI 冒烟、构建与必要的手动操作。

- 真实 Electron 下的失效与重启已验收（提交失败 → 告警/禁用/主进程拒绝 → 重启后恢复）；`PI_FAIL_STORAGE_COUNT` 只用于开发验收，完成后写标记，重启不再注入
- 安装环境（打包后）的失效提示与重启入口仍未验收，属于打包项；纯 Node 装配验证不能代替平台验收
- 增加模型设置入口，并处理旧版留下的非 root 空模型会话；不能通过覆盖已保存模型来修复缺配置
- 安装包配置入口与分发验收仍未完成，开发仓库 `.env` 的加载不等于安装包配置支持

### 2.2 界面余项

主体已能用（消息、工具卡、审批、排队、流式、Markdown、调试条）。阻塞项之外还有体验细节：

- 会话标题、首条消息摘要和最后活动时间已实现；忙碌/排队标记仍需随任务结束刷新，当前会残留
- 自动重试与终态失败已有错误横幅，但没有「重试」按钮或倒计时
- 工具结果只能回看文本，没有「打开文件 / 复制路径」这类动作
- 没有键盘导航（切会话、聚焦输入框）与消息级操作（复制、引用、从某条分叉）
- 滚动是「有新内容就到底」，用户上翻查看历史时会被打断

### 2.3 崩溃恢复实测与打包

故障注入已接入输入提交、工具结果提交前/后、流式片段提交和生成阶段切换。
本地模型与真实远程模型下都已验证强杀恢复：同一输入不重复入队、已提交历史保留、
已提交 partial 保留为中断条目、恢复后续跑完成、任务终态且 `pi.live` 清空；未知结果的旧副作用调用不自动重放。
真实远程模型验证时需把 `--partial-interval-ms` 调小并把输出拉长，否则回答太快、partial 来不及落库就不会命中该检查点。
接下来做 `pnpm package` 的安装包冒烟：确认 `node:sqlite`、asar 路径/ABI、凭证配置与沙箱在安装环境中正常，
并在打包产物内复核失效提示与重启入口；不再新增测试文件。

## 3. V1 不做

- 多窗口同时写同一会话（单写者下要额外做租约）。
- 云端同步、多设备。
- 多进程 / 多实例打开同一 SQLite 文件。
- 插件市场、远程安装工具包。
- 自定义模型协议（除 OpenAI 兼容的 provider 外）。
- 移动端。

这些是边界而不是承诺：先保证前四项不被架构分叉拖住。
