## 2. 待办（按依赖顺序）

### 2.1 聊天界面

渲染进程持有只读副本：流式与最终结果不同显、工具卡 `running→done` 不重复、排队可见、停止不伪造消息、丢帧 resync。

当前页（`apps/desktop/src/renderer/src/App.tsx`）是接线验收用的最小实现：条目/工具/审批能看能点，
但没有 Markdown 渲染、没有分叉/压缩入口、没有错误呈现（`pi.provider` 的失败目前只在会话记录里）。

### 2.2 崩溃恢复实测与打包

`PI_CRASH_POINT` 五类场景各留「重启后第一次看到了什么」的证据；随后 `pnpm package` 做打包冒烟，
确认 `node:sqlite` 在 asar 与打包后的路径/ABI 正常。

### 2.3 后续能力（可与界面并行）

| 能力 | 依赖 | 说明 |
|---|---|---|
| 知识库（`@pi/ext-kb`） | 工具与存储 | `raw/` 只读、`wiki/` 可重建；ingest 是 Task，可从检查点续跑 |
| 工具自举（`@pi/ext-toolsmith`） | 工具模型 + 文件写入 | 生成 → 静态校验 → 子进程试跑 → 人工确认安装 → 版本化热替换 |
| 智能 UI（`@pi/ext-smartui`） | 副本 + 流式渲染 | DSL 是不可信输入，校验器先于渲染器 |

## 3. V1 不做

- 多窗口同时写同一会话（单写者下要额外做租约）。
- 云端同步、多设备。
- 多进程 / 多实例打开同一 SQLite 文件。
- 插件市场、远程安装工具包。
- 自定义模型协议（除 OpenAI 兼容的 provider 外）。
- 移动端。

这些是边界而不是承诺：先保证前四项不被架构分叉拖住。
