## 2. 待办（按依赖顺序）

### 2.1 运行时恢复与配置余项

默认启动、新建会话、终态错误与宿主失效处理已实现。失效时停止操作、结算待审批、清理订阅；
不访问失效存储即可返回失败快照，迟到健康响应不能覆盖失效状态。恢复只通过应用重启，不做进程内热重建。
项目不维护测试文件，默认验收为静态检查、CLI 冒烟、构建与必要的手动操作。

- 真实 Electron 下的失效与重启已验收（提交失败 → 告警/禁用/主进程拒绝 → 重启后恢复）；`PI_FAIL_STORAGE_COUNT` 只用于开发验收，完成后写标记，重启不再注入
- 安装环境（打包后）的失效提示与重启入口仍未验收，属于打包项；纯 Node 装配验证不能代替平台验收
- 模型设置入口已接入（右上角「模型」）：环境变量优先；否则用应用内配置，密钥经 safeStorage 加密存 `userData`。
  保存只影响新会话；缺模型的旧会话（含根）补一次默认模型，不覆盖已有选择。真实 Electron 已验：保存 → 新会话获得真实回答 → 重启后配置仍生效；密钥文件与 SQLite 均无明文
- 安装包内配置与分发验收仍未完成：打包后没有 `.env`，需要复验应用内设置能否完成首次配置

### 2.2 界面余项

主体已能用（消息、工具卡、审批、排队、流式、Markdown、调试条）。阻塞项之外还有体验细节：

- 忙碌/排队标记已随 `submission` 推送防抖刷新会话列表：真实 Electron 里已验证 `busy` 由 true 自动回到 false（排队走同一路径，本地模型太快未抓到 `queued>0` 窗口）
- 失败重试已接入：终态失败横幅带「重试」，复用失败那次输入的原文并用新的 `requestId`（实测 submission 8→14、两条 user 条目文本一致）；自动重试期间显示「N 秒后重试」倒计时（实测 12→4 秒）
- 工具结果已可「复制路径 / 打开文件」：历史工具结果与运行中的工具卡都带动作；打开走主进程 `shell.openPath`，
  路径按工作区真实路径校验（实测拒绝绝对越界、`..` 逃逸与软链指向外部）。`file://` 下 Clipboard API 不可靠，复制改走主进程
- 没有键盘导航（切会话、聚焦输入框）与消息级操作（复制、引用、从某条分叉）
- 滚动跟随已修：内容增长只有在用户没动过 `scrollTop` 时才贴底；流式中上翻后不会被拽回，并显示「回到最新」。真实 Electron 已验证贴底、上翻保持、流式增长不回拽、点回底部

### 2.3 崩溃恢复实测与打包

故障注入已接入输入提交、工具结果提交前/后、流式片段提交和生成阶段切换。
本地模型与真实远程模型下都已验证强杀恢复：同一输入不重复入队、已提交历史保留、
已提交 partial 保留为中断条目、恢复后续跑完成、任务终态且 `pi.live` 清空；未知结果的旧副作用调用不自动重放。
真实远程模型验证时需把 `--partial-interval-ms` 调小并把输出拉长，否则回答太快、partial 来不及落库就不会命中该检查点。
打包冒烟结论：`pnpm package:dir`（关掉依赖重建、只出 `.app`）约 2 分钟。产物内已验证
`node:sqlite`、safeStorage 加密、Seatbelt、无 `.env` 首次配置、真实对话，以及清除密钥后继续生成。
打包与安装验收通过。此前的「拷出后不进主进程」不是签名问题，而是产物缺依赖：
主进程把 `@earendil-works/*` 留在外部，asar 里又排除了 `node_modules`，等于只能“借用”仓库里的依赖
（在 `release/mac-arm64` 里能跑，拷走就 `MODULE_NOT_FOUND`）。已改为把生产依赖打进 asar，仓库外启动正常。
剩余：签名/公证（当前 adhoc，拷贝后 `codesign --verify` 报 resources 缺失）、`pnpm gate` 之外的安装包系统级验收。

## 3. V1 不做

- 多窗口同时写同一会话（单写者下要额外做租约）。
- 云端同步、多设备。
- 多进程 / 多实例打开同一 SQLite 文件。
- 插件市场、远程安装工具包。
- 自定义模型协议（除 OpenAI 兼容的 provider 外）。
- 移动端。

这些是边界而不是承诺：先保证前四项不被架构分叉拖住。
