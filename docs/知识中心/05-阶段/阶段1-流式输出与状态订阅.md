# 阶段 1：流式输出与状态订阅

> **目标**：不用 UI，只用 `watch()` 把回答「边生成边打印」，并理解每一帧是什么。
> **预计**：1 天。**产出**：一个帧日志 + 一个最小 replica 应用器。

---

## 1. 前置概念

- **提交边界**：屏幕上的每个字都来自一次已落盘的 commit。流式不是「模型推给浏览器」，而是「Harness 定期提交部分回答」。
- **默认 100ms 一批**（`settings.progress.partialIntervalMs`）。你会看到文字成段出现，不是逐字。
- **`ConversationView`** = 会话记录 + 当前活跃 entries + 五个内置文档。
- **`pi.live.generation.message`** 是正在生成的那条 assistant；提交完成后它消失，正式 entry 出现。
- **`watch()` 给 ops**，`viewState()` 不给。跨进程要 ops。
- **帧可能是整帧**（`[["r", value]]`），必须能处理。

## 3. 架构位置与模块协作

```
scripts/01-stream.ts
   │
   ├─ watch = await root.watch(ctx)
   ├─ console.log("初始:", watch.value.entries.length)
   ├─ watch.start(async (value, ops, ctx) => { ... })
   ├─ submit(...)
   └─ await submission.wait(ctx)
          │
          └─ 等 watch 的最后一帧落定后 stop
```

这一阶段仍然**没有 Electron**。你要在终端里模拟「渲染进程」：

```
frame → replica = apply(replica, ops) → 打印 replica 里当前的回答
```

---

## 4. API 清单

| 目的 | API | 注意 |
|---|---|---|
| 订阅 | `conversation.watch(ctx)` | 返回 `WatchHandle<ConversationView>` |
| 初始值 | `watch.value` | attach 时快照，同步可用 |
| 启动 | `watch.start((value, ops, ctx) => Promise<void>)` | 不内联回调 |
| 停止 | `watch.stop()` / `watch.closed` | 幂等 |
| 应用 | `applyImmutable(prev, ops)` | 返回新值 |
| 判整帧 | `isBase(ops)` | `[["r", ...]]` |
| 本地订阅 | `conversation.viewState(ctx)` | `AttachedReplicatedState` |
| 调频率 | `settings.progress.partialIntervalMs` | 默认 100 |
| 读 live | `view.docs["pi.live"]` | 类型 `JsonObject`，先打印 |

## 5. 手写任务

### 5.0 落地顺序与可手写代码

先完成纯函数，再接入订阅脚本；下面的 `import` 路径按项目实际导出调整。

```ts
import { applyImmutable, isBase, type Op } from "@earendil-works/chord/delta"; // 引入不可变应用帧和整帧判断工具。
import type { ConversationView } from "@earendil-works/pi-durable"; // 引入会话副本的类型。
export type Replica = ConversationView; // 让副本类型与会话视图保持一致。
export function applyFrame(prev: Replica | undefined, ops: readonly Op[]): Replica | undefined { // 定义不修改旧副本的帧应用函数。
  if (ops.length === 0) return prev; // 空帧直接保留当前副本。
  return isBase(ops) ? applyImmutable(undefined, ops) : applyImmutable(prev, ops); // 整帧覆盖而增量帧基于旧副本合并。
} // 结束帧应用函数。
const watch = await root.watch(ctx); // 先取得含初始快照的订阅句柄。
let replica = watch.value; // 用初始快照初始化本地副本。
await watch.start(async (value, ops) => { // 启动后只快速处理每一帧。
  replica = applyFrame(replica, ops) ?? value; // 优先按操作重建副本并在必要时回退到回调值。
  const live = replica.docs["pi.live"] as { generation?: { message?: unknown } } | undefined; // 安全读取实时生成文档。
  console.log({ ops: ops.length, base: isBase(ops), live }); // 输出帧摘要以便观察流式变化。
}); // 结束订阅回调注册。
const submission = await root.submit({ type: "input", content: "用 200 字分三点解释状态订阅。" }, ctx); // 提交一个足够长的测试问题。
await submission.wait(ctx); // 等待本次提交完成而不是猜测时间。
await new Promise((resolve) => setTimeout(resolve, 200)); // 留出最后一帧抵达副本的时间。
await watch.stop(); // 显式停止订阅以释放资源。
```

### 5.1 `scripts/01-stream.ts`

写一个脚本，完成：

1. 打开 Harness（可以复用阶段 0 的 models）。
2. `watch = await root.watch(ctx)`。
3. 打印 `watch.value` 的结构（`entries.length`、`docs` 的 key）。
4. `watch.start(...)`，在回调里：
   - 记录 `ops.length`、`isBase(ops)`；
   - 更新一个本地 `replica`；
   - 打印「当前回答文本」。
5. 提交一个会生成较长回答的问题（「用 200 字解释……并分三点」）。
6. `await submission.wait(ctx)`。
7. 再等 200ms，`await watch.stop()`，打印统计。

### 5.2 `scripts/01-replica.ts`

把「应用一帧」抽成纯函数：

```ts
type Replica = ConversationView;

export function applyFrame(prev: Replica | undefined, ops: readonly Op[]): Replica {
  // 如果是整帧：applyImmutable(undefined, ops)
  // 否则：applyImmutable(prev, ops)
}
```

要求：

- 不允许 mutate `prev`。
- `ops.length === 0` 时返回 `prev`。
- 用 `isBase` 判断，不要看 `ops[0][0] === "r"`（虽然等价，但语义不同）。

### 5.3 `scripts/01-live.ts`（可选）

单独打印 `pi.live` 的变化：

```ts
const live = replica.docs["pi.live"];
console.dir(live, { depth: 6 });
```

观察 `generation.message` 在什么时候出现、什么时候消失。

## 6. 实现提示

- **先拿 `watch.value` 再 `start()`。** 不能只靠回调，因为 `start()` 不内联、也不重放历史。
- **回调必须快。** 里面只做 `apply` + 打印摘要。不要在回调里 `await` 慢操作，否则会积压（超过 100 帧会折叠）。
- **打印 ops 时只打印前 3 条。** 一帧可能有几十条，全打会淹没终端，也会拖慢回调。
- **文本路径不要猜。** `generation.message` 的 content 是块数组；先 `console.dir` 一次，再写 `text` 提取函数。
- **最终文本做一致性断言**：

  ```
  最后一条 pi.assistant entry 的文本 === replica 里显示的文本
  ```

  不一致说明「部分消息」与「正式 entry」的切换处理错了。

- **统计帧数**：一次 200 字回答大约 10–30 帧。如果上千帧，说明你把 `partialIntervalMs` 调太小了。
- **整帧出现的时机**：通常在你落后太多、或重新 attach 时。测试时手动 `await sleep(2s)` 在回调里制造积压，观察折叠。

## 7. 调试方法

| 想知道 | 做法 |
|---|---|
| 有没有收到帧 | 回调第一行 `console.log(ops.length)` |
| 是增量还是整帧 | `console.log(isBase(ops))` |
| 文本在哪 | 打印 `Object.keys(generation.message ?? {})` 与 `message.content` |
| 为什么停更 | `wait()` 是否 resolve；`inspect()` 是否有 running 任务 |
| 为什么重复 | 检查是不是把累积文本当增量打印 |
| 积压折叠 | 在回调里 `await sleep(2000)`，看后续帧是否变成整帧 |

**保存一份帧日志**（只存 `{seq-like index, ops.length, isBase, textLength}`），阶段 6 调试渲染时会用到。

## 8. 验收标准

- [ ] 终端能在回答生成过程中持续输出，而不是最后一次性出现。
- [ ] 至少观察到 5 帧以上。
- [ ] 最终打印的文本与 `entries` 里最后一条 assistant 的文本完全一致。
- [ ] 能说出某一帧是增量还是整帧，并解释原因。
- [ ] `applyFrame` 不修改旧值：保存 `const before = replica`，应用后 `before` 仍可读且内容不变。
- [ ] `watch.stop()` 后不再有回调；`watch.closed` 的 reason 是 `"stopped"`。
- [ ] 把 `partialIntervalMs` 从 100 改成 500，帧数明显减少，最终文本不变。

## 10. 常见失败

| 现象 | 原因 | 修法 |
|---|---|---|
| 一直没输出，最后一次性出现 | 只 `await wait()`，没订阅 | 先 `watch.start()` |
| 收不到第一帧 | 只依赖回调，丢掉了 `watch.value` | 用 `.value` 初始化 replica |
| 文字重复 | 每次打印累积文本却当增量拼接 | 直接打印 replica 当前值 |
| 文字倒退 | 整帧被当增量应用 | `isBase` 时覆盖 |
| 回调里报错后 watch 结束 | 回调抛错 | `closed` 会给出 `listener_error`；回调内 try/catch 并记录 |
| 帧越来越少 | 积压触发折叠 | 减少回调耗时 |
| 文本结构取不到 | 把 content 当字符串 | 先 `console.dir`，按块数组处理 |
| `stop()` 后进程不退出 | 还有别的 timer | 检查 `wait()` / `setTimeout` |
