# 阶段 7：知识库

> **目标**：把 `raw/` 里的原始笔记变成 `wiki/` 里可检索、可引用、可追溯的页面。
> **预计**：1 周。**产出**：4 个 kb 工具 + 一个可恢复的 ingest 任务 + index/log/lint。

---

## 1. 前置概念

- **raw 是事实，wiki 是整理。** `raw/` 只读、不改；`wiki/` 是生成物，可以重建。
- **ingest 是 Task，不是 Tool。** 它是分钟级、多阶段、可中断的工作；Tool 只能整体重来。
- **每个阶段一个检查点。** 崩溃后从上一个 phase 继续，不从头。
- **幂等靠内容哈希。** 同一文件未变就跳过；变了就重写同一页面，而不是追加新页面。
- **检索先做词法，不做向量。** V1 的语料在几百页量级，建立 embedding 索引的收益抵不过复杂度。
- **模型只读 wiki，不直接读 raw。** 这样引用稳定，也避免把半成品喂给模型。
- **索引和日志是普通文件。** 它们能被 git diff、能被用户手改，不要藏进数据库。

## 3. 架构位置与模块协作

```
userData/workspace/
├─ raw/                用户拖入的原始文件（只读）
├─ wiki/               生成页面（可重建）
├─ index.md            页面清单：标题、摘要、标签、路径
├─ log.md              追加式操作日志
└─ AGENTS.md           给模型的写作约定（页面结构、命名、禁止事项）

packages/extensions/kb/src/
├─ index.ts            defineExtension({name:"kb", tools, tasks, sections})
├─ docs.ts             AppKbDoc（session scope）
├─ wiki/
│  ├─ paths.ts         resolveInside / slug / pagePath
│  ├─ frontmatter.ts   读写 YAML frontmatter（自己写一个最小实现）
│  ├─ index-writer.ts  重建 index.md
│  └─ log.ts           追加 log.md
├─ tools/
│  ├─ kb-search.ts
│  ├─ kb-read.ts
│  ├─ kb-ingest.ts
│  └─ kb-lint.ts
└─ tasks/ingest.ts     defineTask({ name:"app.kb.ingest", ... })
```

触发路径：

```
拖入文件 → IPC "kb.ingest"
              └─ conversation.commit(tx => tx.createTask(KbIngestTask, {relPath}, {ownership:{kind:"conversation"}, background:true}))

模型需要知识 → 调用 kb_search → 得到路径与摘要 → 调用 kb_read → 在回答里引用
```

**注意**：ingest 也可以由工具调用触发（`kb_ingest`），但那是「模型决定收录」。人的拖入走 IPC，二者最终都创建同一个 Task。

## 4. API 清单

| 目的 | API | 注意 |
|---|---|---|
| 定义任务 | `defineTask({name, version, initial, phases, abort})` | 每个 phase 必须提交新状态或终态 |
| 建任务（IPC） | `conversation.commit(tx => tx.createTask(task, input, {ownership:{kind:"conversation"}, background:true}), ctx)` | `tx.createTask` 只有 3 个参数，无 ctx |
| 建任务（工具） | `api.createTask(task, input, {ownership:{kind:"conversation"}, background:true}, ctx)` | `ToolExecutionApi` 版本带 ctx |
| 提交检查点 | `rt.commit((tx, current) => nextState, ctx)` | 返回 `{status:"running", checkpoint}` 或终态 |
| 结束 | `rt.commit(() => ({status:"terminal", outcome:{status:"completed", result}}), ctx)` | `failed` 用 `{status:"failed", error:{message}}` |
| 环境 | `rt.env(ctx)` | 可能 undefined；返回 `Result` |
| 任务文件读写 | `env.readTextFile/writeFile/createDir/listDir/renameFile` | 都返回 `{ok,value}|{ok:false,error}` |
| 模型 | `rt.models.completeSimple(model, {messages}, ctx)` | model 从 `rt.agent(ctx).model` 解析 |
| 长等待 | `rt.sleepUntil(until, checkpoint, ctx)` | 不要用 `sleep` |
| 文档 | `tx.doc(AppKbDoc, conversationId)` | 只能在该 commit 内 |
| 工具参数 | TypeBox `Type.Object` | |
| 任务观察 | `harness.watchTaskGraph(ctx)` | UI 任务面板 |

`rt.agent(ctx)` 的 `model` 是 `ModelRef`（`{provider, id}` 形状，以类型为准）；缺失时给出「当前会话没有选模型」的明确错误，不要静默换模型。

## 5. 手写任务

### 5.0 落地顺序与可手写代码

先完成路径和哈希这两个确定性基础，再把 ingest 拆成可恢复 phase；所有文件路径都从显式工作区根目录计算。

```ts
import { createHash } from "node:crypto"; // 引入计算内容哈希的标准库。
import path from "node:path"; // 引入可靠的路径规范化能力。
export function resolveInside(root: string, relPath: string): string { // 定义只接受工作区内部相对路径的函数。
  if (path.isAbsolute(relPath)) throw new Error("不允许绝对路径"); // 先拒绝绕过根目录的绝对路径。
  const target = path.resolve(root, relPath); // 将相对路径展开为规范绝对路径。
  const relative = path.relative(root, target); // 计算目标相对根目录的位置。
  if (relative.startsWith("..") || path.isAbsolute(relative)) throw new Error("路径超出工作区"); // 拒绝父级逃逸和跨卷结果。
  return target; // 返回已验证的工作区内目标。
} // 结束路径边界函数。
export function contentHash(text: string): string { // 定义可用于幂等判断的内容指纹函数。
  return `sha256:${createHash("sha256").update(text).digest("hex")}`; // 生成带算法前缀的稳定 SHA-256 哈希。
} // 结束内容哈希函数。
export const KbIngestTask = defineTask({ // 定义可从检查点继续的知识库任务。
  name: "app.kb.ingest", // 固定任务名以兼容已持久化状态。
  version: 1, // 用版本标识任务状态结构。
  initial: ({ relPath }) => ({ phase: "read", relPath }), // 仅创建纯初始状态而不执行 I/O。
  phases: { read: async (rt, state, ctx) => { const env = await rt.env(ctx); if (!env) return { status: "failed", error: { message: "缺少文件执行环境" } }; const raw = await env.readTextFile(state.relPath); return rt.commit(() => ({ status: "running", checkpoint: { ...state, phase: "summarize", hash: contentHash(raw) } }), ctx); } }, // 读取原文后仅提交下一阶段所需的检查点。
}); // 结束 ingest 任务定义。
```

### 5.1 `wiki/paths.ts`

- `workspaceRoot` 从参数传入，不读全局。
- `resolveInside(root, relPath)`：`path.resolve` + `path.relative` 校验；拒绝 `..`、绝对路径、符号链接逃逸（`env.canonicalPath` 后再比一次）。
- `slugify(filename)`：保留中文，替换空白与标点为 `-`，最长 80 字符。
- `pagePath(relPath)`：`wiki/<slug>.md`；冲突时追加短哈希。

### 5.2 `wiki/frontmatter.ts`

最小实现，只支持：

```
---
title: ...
source: raw/xxx.md
hash: sha256:...
updatedAt: 2026-...
tags: [a, b]
---
```

函数：`parse(text)`、`stringify(meta)`、`replaceBody(text, body)`。不要引入 YAML 库，除非你确实需要嵌套结构。

### 5.3 `docs.ts`

`AppKbDoc`（session scope，`history:"latest"`）：

```ts
{
  version: 1,
  root: string,
  sources: {
    [relPath: string]: {
      status: "new" | "ingesting" | "indexed" | "failed",
      hash: string,
      page: string | null,
      taskId: number | null,
      updatedAt: number,
      error?: string,
    }
  },
  lastLintAt: number | null,
}
```

`checkpointWhen`：`ops.length > 32 || info.deltasSinceBase > 64`。来源超过几千条时再拆 family，不要提前拆。

### 5.4 `tasks/ingest.ts`

Phase 状态机（输入 `{relPath}`）：

```
read     读文件、算 hash、检查 app.kb → 已索引且 hash 相同则直接 terminal(skipped)
         否则 commit {phase:"summarize", hash, title,...} + sources[rel].status="ingesting"
summarize 读 raw，调用模型生成 wiki 正文（超长先截断并记录 truncated）
         commit {phase:"write", body}
write    原子写：临时文件 → rename → wiki/<slug>.md
         commit {phase:"index", page}
index    重建 index.md；追加 log.md；commit sources[rel].status="indexed"
done     terminal {status:"completed", result:{page, skipped:false}}
```

要求：

- **每个 phase 只做一件事**；phase 内的中间结果放任务状态，不要放内存。
- `abort` 必须提交终态（`{status:"aborted"}`），并把 `sources[rel].status` 改为 `failed` 或回滚到 `new`。
- 读文件用 `rt.env(ctx)`；`env` 为 undefined 时任务失败，错误信息写清楚。
- 模型输出必须校验：非空、长度上限（如 64KB）、包含 frontmatter 由你生成而不是模型生成。
- **写入前**确认目标在 `wiki/` 内。
- 同一 `relPath` 已有 `ingesting` 的 live 任务时，不创建第二个；返回已有 `taskId`。

### 5.5 `tools/kb-search.ts`

- 参数：`query`、`limit?`（默认 5）、`tag?`。
- `replay:"safe"`，`executionMode:"parallel"`。
- 实现：遍历 `wiki/*.md`，读 frontmatter 的 title/tags 与正文；按词项命中数 + 标题权重打分；返回 `{path, title, snippet, score}`。
- `output` 是给模型的紧凑列表；`details` 存完整结果（含 snippet 位置）。
- 语料超过 500 页再考虑预建倒排索引；之前不要过度设计。

### 5.6 `tools/kb-read.ts`

- 参数：`path`、`offset?`、`limit?`（行）。
- `replay:"safe"`。
- 只允许读 `wiki/` 与 `index.md`、`log.md`、`AGENTS.md`；**不允许读 raw**（保持「wiki 是唯一知识面」）。
- 输出带行号；超限截断并说明。

### 5.7 `tools/kb-ingest.ts`

- 参数：`path`（raw 内相对路径）。
- 校验路径 → 创建 Task（`api.createTask`）→ 立即返回 `{taskId, status:"started"}`。
- `replay:"unsafe"`（默认）：重复调用会创建新任务，但任务内部按 hash 跳过；这是可接受的。
- 如果已有 live 任务，返回已有 taskId。

### 5.8 `tools/kb-lint.ts`

- 检查：死链（`[[page]]` / 相对链接指向不存在页面）、缺 frontmatter、index 里有但文件不存在、文件存在但 index 没有、重复 title。
- 返回 `{issues: [...], counts}`；`details` 给 UI 表格。
- `replay:"safe"`。

### 5.9 `index.ts`

`defineExtension({ name: "kb", tools: [...], tasks: [KbIngestTask], sections: [section("kb.rules", ...)] })`。

`section` 的内容要短：告诉模型「先 kb_search，再 kb_read；引用时写页面路径；不要编造不存在的页面」。

### 5.10 IPC `kb.ingest` / `kb.sources`

- `kb.ingest`：校验 → commit 建任务 → 返回 taskId。
- `kb.sources`：`snapshot(AppKbDoc, ctx)` 的来源列表（脱敏为相对路径）。
- 任务进度用 `watchTaskGraph` 推给渲染进程；本阶段可以先只在任务面板显示。

### 5.11 `scripts/07-kb.ts`

不经过 UI 的端到端脚本：

1. 准备 `workspace/raw/sample.md`。
2. 建任务并等它 terminal。
3. 打印生成的 wiki 页面、index 行、log 行。
4. 用 `kb_search` 查一个词，`kb_read` 读结果。
5. 再跑一次 ingest，确认 `skipped:true`。
6. 修改 raw 文件再跑，确认页面被覆盖而不是新增。

## 6. 实现提示

- **phase 名一旦发布不要改。** 它写在任务状态里；改名会让旧任务无法恢复。
- **任务状态保持小。** 不要把整篇文档塞进 checkpoint；需要时重新读文件。正文可以放，但要设上限。
- **`rt.commit` 回调里只用 `tx`。** 调用 `snapshot()` / `getTask()` 会死锁（`ReadAfterWrite`）。
- **模型请求放在 phase 里，不放 `initial`。** `initial` 只做纯计算。
- **失败要写进 `app.kb`。** 否则 UI 只看到任务失败，不知道哪个来源失败。
- **`write` 用临时文件 + rename**，避免半截文件被 `kb_search` 读到。目标与临时文件都在 wiki 目录内。
- **索引是重建，不是增量拼接。** 每次 ingest 后从文件系统重新扫一遍，简单且不会漂移。
- **log.md 只追加。** 记录时间、来源、hash、生成页面、任务 id；不要写模型全文。
- **ingest 的时间戳用 `rt.now()`。** 不要 `Date.now()`，否则测试与恢复不可复现。
- **模型输出的引用**：要求它使用 `[title](../wiki/page.md)` 形式；lint 检查这些链接。
- **并发 ingest**：两个任务同时重建 index 会互相覆盖。V1 用「index 写入串行化」——在 `app.kb` 里放一个版本号，写入前比对；冲突就重跑 `index` phase。

## 7. 调试方法

| 想知道 | 做法 |
|---|---|
| 任务卡在哪 | `harness.inspect(ctx)`、`watchTaskGraph` |
| 任务状态里有什么 | `harness.getTask(id, ctx)`，打印 `state.checkpoint` |
| 为什么跳过 | 打印 raw 的 hash 与 `app.kb.sources[rel].hash` |
| 页面没生成 | phase 是否 commit；`env` 是否 undefined |
| 搜索没结果 | 打印索引到的页面数与词项；先 `kb_lint` |
| 链接断了 | `kb_lint` 的 issues |
| 崩溃后重跑几遍 | log.md 与任务检查点 |
| 模型输出乱 | 打印 prompt 与原始返回长度；先限制输入长度 |

**不要通过删库来「重试」。** 用 `retryTask` 或重新 ingest；删库会丢掉验证证据。

## 8. 验收标准

- [ ] 把一个 markdown 文件放进 `raw/`，触发 ingest，`wiki/` 出现页面且带 frontmatter。
- [ ] `index.md` 有该页面一行；`log.md` 追加了一条。
- [ ] `kb_search` 能找到它，`kb_read` 能读出带行号的内容。
- [ ] 相同内容再次 ingest → `skipped`，不产生第二个页面。
- [ ] 修改 raw 后 ingest → 同一页面被覆盖，log 新增一条。
- [ ] ingest 到一半 `kill -9`，重启后任务从上一个 phase 继续，最终状态一致。
- [ ] 停掉 Harness（`abortTask`）后，来源状态不是 `ingesting`。
- [ ] 路径 `../` / 绝对路径 / `wiki/../raw/x` 全部被拒绝。
- [ ] `kb_read` 读 raw 被拒绝。
- [ ] `kb_lint` 能报出一个人为制造的死链。
- [ ] 两个来源同时 ingest，index 不丢行（用串行化或冲突重跑）。
- [ ] 模型回答里引用 wiki 页面时，路径真实存在。

## 10. 常见失败

| 现象 | 原因 | 修法 |
|---|---|---|
| 任务一直 pending | 创建后没 `resume()` | 启动固定 |
| 任务 faulted | 某 phase 没 commit | 每个 phase 必须提交状态 |
| 恢复后从头跑 | 检查点没写，或 phase 名变了 | 固定 phase 名；每步 commit |
| 重复生成页面 | slug 不稳定 / 未按 hash 跳过 | 固定 slug 规则 + 来源表 |
| index 少行 | 并发重建互相覆盖 | 串行化或版本号重试 |
| 搜索永远 0 结果 | 只搜了 index 没搜正文 | 明确搜索范围 |
| 模型读不到页面 | `kb_read` 拒绝了 wiki 路径 | 检查 resolveInside |
| 半截文件被索引 | 直接写目标文件 | 临时文件 + rename |
| 页面内容被模型加了 frontmatter | 让模型生成整页 | frontmatter 由代码生成 |
| 崩溃循环 park | 某个 phase 每次崩 | 用 `inspect()` 找 phase；修复后再 `retryTask` |
