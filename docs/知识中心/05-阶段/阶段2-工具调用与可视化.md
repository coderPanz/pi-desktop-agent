# 阶段 2：工具调用与可视化

> **目标**：让模型能读写工作区文件、执行命令；你能在终端里看到「工具正在做什么」。
> **预计**：2–3 天。**产出**：一个 coding 扩展 + 一个工具执行日志。

---

## 1. 前置概念

- **工具是契约**：name + description + TypeBox schema，模型据此决定调用。
- **意图先落盘**：工具执行前，调用意图已经是一个 commit。崩溃后据此判断重放。
- **三个通道**：`output` 给模型、`details` 给 UI、`structuredOutput` 给程序。
- **`env` 可能不存在**：工具必须判空，不能假设一定有文件系统。
- **权限在 Hook 里**，不在工具里。
- **工具结果也是一条 entry**，与 assistant 的 tool_calls 用 id 关联。

## 4. API 清单

| 目的 | API | 注意 |
|---|---|---|
| 定义工具 | `defineTool({...})` | TypeBox `parameters` |
| 组合扩展 | `defineExtension({name, tools, hooks})` | 名字稳定 |
| 安装 | `registry.install(ext)` | 同名覆盖 |
| 环境 | `api.env` | 可能 undefined |
| 进度 | `api.output(chunk)` / `api.details(v, ctx)` | 通道不同 |
| 嵌套调用 | `api.executeTool(name, args, ctx, {key})` | 结果不进转录 |
| 审批 | `hook(ToolTask, { beforeTool, afterTool })` | 返回 `{block}` |
| 配置工具集 | `conversation.configure({ tools | modelTools }, ctx)` | 名字或对象 |
| 观察工具 | `view.docs["pi.live"].tools` | `ToolSlot[]` |

## 5. 手写任务

### 5.0 落地顺序与可手写代码

先抽出路径边界与策略纯函数，再让工具和 Hook 共用它们；下面示例的类型导入按项目版本调整。

```ts
import path from "node:path"; // 引入跨平台路径工具。
export function resolveInside(root: string, userPath: string): string { // 定义工作区边界校验函数。
  const target = path.resolve(root, userPath); // 将用户路径规范化为绝对路径。
  const relative = path.relative(root, target); // 计算目标相对工作区的路径。
  if (relative.startsWith("..") || path.isAbsolute(relative)) throw new Error("路径超出工作区"); // 拒绝父级逃逸和跨盘绝对路径。
  return target; // 只返回已验证的工作区内路径。
} // 结束路径校验函数。
export function classify(command: string): "allow" | "ask" | "deny" { // 定义不依赖 I/O 的审批策略。
  if (/rm\s+-rf\s+\//i.test(command) || /curl\b[^|]*\|\s*sh/i.test(command)) return "deny"; // 拒绝破坏性删除和管道执行脚本。
  if (/\bgit\s+push\b|\bnpm\s+(install|i)\b|\.env\b/i.test(command)) return "ask"; // 将推送和依赖安装交给用户确认。
  return "allow"; // 其余命令默认允许。
} // 结束审批策略函数。
export const ReadFileTool = defineTool({ // 定义可安全重放的读文件工具。
  name: "read_file", // 使用稳定的工具注册名。
  parameters: Type.Object({ path: Type.String(), offset: Type.Optional(Type.Integer()), limit: Type.Optional(Type.Integer()) }), // 明确声明模型可传的参数。
  replay: "safe", // 读取文件不会产生外部副作用。
  async execute(args, api) { // 实现一次实际工具调用。
    const file = resolveInside(api.env!.cwd, args.path); // 在执行环境的工作区内解析路径。
    const lines = (await api.env!.readTextFile(file)).split("\n"); // 读取文本并按行拆分。
    const slice = lines.slice(args.offset ?? 0, (args.offset ?? 0) + (args.limit ?? 200)); // 截取受限的行区间。
    return { output: slice.map((line, index) => `${(args.offset ?? 0) + index + 1}: ${line}`).join("\n"), details: { path: args.path, totalLines: lines.length, truncated: slice.length < lines.length } }; // 返回模型文本和 UI 详情。
  }, // 结束工具执行函数。
}); // 结束工具定义。
```

### 5.1 四个工具

**`read-file.ts`**

- 参数：`path`、`offset?`、`limit?`。
- 行为：相对工作区解析路径；越界返回 `isError`；带行号输出；超过限制截断。
- `replay: "safe"`。
- `details`：`{ path, totalLines, truncated }`。

**`list-dir.ts`**

- 参数：`path?`、`depth?`。
- 行为：只列目录与文件名，不递归太深；忽略 `node_modules` / `.git`。
- `replay: "safe"`。

**`write-file.ts`**

- 参数：`path`、`content`。
- 行为：先读旧内容（用于 `details.diff` 或备份），再写；返回写入字节数。
- 默认 `replay`（unsafe）；`executionMode: "sequential"`。
- **必须在 Hook 里审批。**

**`bash.ts`**

- 参数：`command`、`cwd?`、`timeoutMs?`。
- 行为：`api.env` 执行；stdout/stderr 合并；超过限制截断；超时杀掉。
- 默认 unsafe；sequential。
- `details`：`{ command, exitCode, durationMs }`。

### 5.2 审批 Hook

写 `hooks/approval.ts`：

```ts
hook(ToolTask, {
  async beforeTool(call, api, ctx) {
    // 只处理 bash / write_file
    // 纯函数 classify(command | path, args) → "allow" | "ask" | "deny"
    // ask 时用 readline 询问，deny 时返回 { block: "..." }
  },
});
```

要求：

- `classify` 是**纯函数**，单独放 `policy.ts`，可单测。
- 下面这些直接 deny：`rm -rf /`、写工作区外、`curl | sh`、读 `~/.ssh`。
- 下面这些 ask：删除文件、`git push`、安装依赖、写 `.env`。
- 其余 allow。

### 5.3 `scripts/02-tools.ts`

1. 建 registry，install coding 扩展。
2. 打开 Harness，`root.configure({ tools: ["read_file","list_dir","write_file","bash"] }, ctx)`。
3. `watch` 并在回调里打印 `pi.live.tools` 的摘要（name/status/output 前 3 行）。
4. 依次提交三个任务：
   - 「列出工作区文件」
   - 「读 README.md，总结三点」
   - 「创建一个 hello.txt，内容是 hello」
5. 每个任务 `await submission.wait(ctx)`，打印最终回答。

### 5.4 `tools/policy.test.ts`

给 `classify` 写至少 10 条用例（含大小写、参数拼接、`;` 串联命令）。

## 6. 实现提示

- **路径校验统一走一个函数**：

  ```
  resolveInside(root, userPath) → 绝对路径 或 抛错
  ```

  用 `path.resolve` + `path.relative` 判断是否以 `..` 开头。不要用字符串 `startsWith`（`/root2` 会被 `/root` 误判）。

- **`bash` 的输出要限流**：stdout/stderr 可能无限。用 `outputLimits` 或自己只保留头/尾 N KB。全量放 `details` 也会写放大，二选一。
- **`details` 里不要放 Buffer**。JSON 化会变成巨大的对象数组。
- **让模型更容易调用**：description 写清楚「相对路径」「不要用于二进制」。读文件失败时，`output` 里给出下一步（「用 list_dir 查看目录」）。
- **`configure({ tools })` 的语义**：给定则替换。先只给 4 个，避免模型调用不存在的工具。
- **`executionMode: "sequential"`** 会让**整轮**顺序执行，不只是该工具。这是有意的：写文件时不要和读并发。
- **不要用 `process.cwd()`** 当工作区。脚本里显式传一个 `workspace` 变量。

## 7. 调试方法

| 现象 | 查什么 |
|---|---|
| 模型不调用工具 | `tools` 配置是否包含名字；description 是否说清用途 |
| 调用但参数错 | 打印 tool_call 的 arguments；看 schema 是否太松 |
| 工具报 `env undefined` | `Harness.open` 的 `env` 是否给了 |
| 文件路径越界 | 打印 `path.resolve` 的结果与 root |
| 命令卡住 | 是否设了 timeout；是否有子进程未退出 |
| UI 没有详情 | `api.details` 是否调用；`pi.live.tools[].details` 是否有值 |
| 审批没触发 | Hook 是否装在已安装的扩展里；`call.tool` 名字是否匹配 |

`pi.live.tools` 的形状以 [阶段 2 相关类型](../02-PI-Durable/02-API参考.md) 为准；先 `console.dir` 真实值。

## 8. 验收标准

- [ ] 模型能根据问题主动调用 `read_file` / `list_dir`。
- [ ] 读取工作区外的路径被拒绝，且模型能看到可读的错误信息。
- [ ] `bash` 的危险命令被 Hook 拦截；普通命令能执行并返回输出。
- [ ] `write_file` 写完后，文件系统里确实存在该文件。
- [ ] 运行中的工具在 `pi.live.tools` 里状态从 `running` 变为 `done`。
- [ ] 工具结果 entry 与 assistant 的 tool_call 能通过 id 关联。
- [ ] 同一轮里两个 `write_file` 不会并发（sequential 生效）。
- [ ] `policy.test.ts` 全部通过。

## 10. 常见失败

| 现象 | 原因 | 修法 |
|---|---|---|
| `tool not found` | 名字不在 `tools` 配置里 | 用 `configure` 显式给 |
| 参数校验失败 | schema 与模型习惯不符 | 补 description，必要时 `prepareArguments` |
| 工具没执行 | `execute` 抛错被包装成 isError | 看 `pi.live.tools[].diagnostics` |
| 越界没有拦住 | 用了 `startsWith` | `path.relative` 判断 |
| bash 输出丢失 | 超过 limits 被尾部截断 | 调整 `retain` 或分段读 |
| 审批弹窗卡死 | readline 在非 TTY 环境 | 脚本里检测 `process.stdin.isTTY` |
| 崩溃后重复写文件 | `replay` 默认 unsafe 但仍被重跑？ | 确认没有把 replay 写成 safe |
| 工具结果没进模型 | 只写了 `details`，没写 `output` | `output` 才是模型通道 |
