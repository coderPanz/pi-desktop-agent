## 0. 怎么验证一个 SDK API

不要靠搜索结果的二手总结。三步：

```bash
# 1. 取下与你 package.json 完全一致的版本
npm pack @earendil-works/pi-durable@1.4.0
mkdir -p /tmp/inspect && tar -xzf earendil-works-pi-durable-1.4.0.tgz -C /tmp/inspect

# 2. 读类型定义（权威）
sed -n '1,200p' /tmp/inspect/package/dist/harness/types.d.ts

# 3. 运行时确认（版本、导出）
node -p "require('/tmp/inspect/package/package.json').version"
node -e "import('@earendil-works/pi-durable').then(m=>console.log(Object.keys(m).sort()))"
```

判断标准：

- **类型文件里有** → 可以写进文档，标注文件路径。
- **只有 README 提到** → 标注「README 提及，类型未确认」。
- **两者都没有** → 标 🔴，不要写进 API 参考。

| 1.3 | better-sqlite3 适配 `SqliteDatabase` 可行 | 🟡 | 实现 `exec/run/get/all/transaction/close` 六方法，跑 `SqliteStorage.open(db)` + 一次 commit/read | 兜底方案；类型已确认只需六个成员 |
| 1.4 | Electron 主进程 ESM 入口 | 🔴 | 打包后 `main` 指向 `.mjs` 或 `"type":"module"`，启动一次 | 影响构建配置，不影响 API |
| 1.5 | `node:sqlite` 的 WAL 在 macOS/Windows 行为 | 🔴 | 两个平台各跑一次崩溃测试 | 影响恢复与备份策略 |

**1.2 的具体命令**（放进 `app.whenReady()` 之前）：

```ts
try {
  const { DatabaseSync } = require("node:sqlite");
  new DatabaseSync(":memory:").close();
  console.log("node:sqlite ok");
} catch (e) {
  console.error("node:sqlite unavailable", e);
}
```
